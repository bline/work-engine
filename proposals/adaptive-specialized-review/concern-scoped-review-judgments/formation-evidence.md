## Repository observations

### Existing review-artifact proposal

The decided
[`work-engine.revision-bound-review-artifacts`](../revision-bound-review-artifacts/proposal.md)
proposal already protects exact subjects, episodes, findings, truthful empty or
failure outcomes, conflicts, synthesis integrity, applicability, and separation
from downstream authority. Its decision keeps permanent placement provisional
and explicitly reopens when implementation-review, remediation, runtime,
concurrency, or distinct-lifetime evidence requires a different owner.

### Current retained review state

[`independent-review-state`](../../../skills/independent-review-state/SKILL.md)
owns only unfinished operational state for one retained episode. Its current
implementation preserves an episode-wide reviewed subject, findings, unresolved
questions, evidence and claim references, pending action, reviewer generation,
continuity, uncertainty, and retirement. Findings have stable IDs, attribution,
severity, observations, evidence, status, and remediation references.

The current closed state has no first-class immutable `ReviewResult` or
concern-scoped positive `ReviewJudgment` record. A result without findings can
be published, but the state cannot express which exact concern-subject pairs
were materially evaluated, which evidence the reviewer asserted it relied on
for each pair, or why that judgment later remained applicable.

### Existing no-finding semantics

The agent-instruction-review finding contract already requires a no-finding
result to preserve applicability, subject identity, inspected material,
decisive evidence, and limitations while disclaiming completeness, acceptance,
self-certification, and correctness beyond the bounded subject. The current
episode schema cannot preserve that granularity directly.

### Migration and UI consumers

The App Server skills-migration plan's S9 candidate already calls for a
provider-neutral implementation-review contract and episode service with exact
subjects, evidence requirements, findings, verdicts, remediation, recovery,
replacement, and uncertainty. S10 through S13 consume role realization,
claim-backed findings, raw event normalization, behavior analysis,
adjudication, profile admission, and reviewer-coverage research.

The control-plane causal-observability design already separates observed,
mechanically derived, semantically interpreted, counterfactual, and recommended
statements; assigns review episode and finding meaning to their owners; and
requires two-way evidence drill-down. Concern-scoped results would supply a
currently missing canonical source for positive review provenance.

### Codebase Memory feasibility

The active claim-maintenance proposal's repository evidence identifies
Codebase Memory as the probable current-world projection and traversal provider
after a bounded owner-isolated, generation-bound, atomic, unresolved-preserving
`sync_projection` extension. Current Codebase Memory does not expose generic
projection ingestion or preserve arbitrary external graph records through full
publication. This proposal consumes the protected synchronization consequence,
not the provisional mechanism name or provider-specific query interface.

## Formation judgments

These are revisable model judgments, not accepted contracts:

- implementation review now supplies the discriminating evidence needed to
  split immutable result and judgment meaning from unfinished episode state;
- stable concern identity is required to distinguish selective semantic review
  from perspective-wide coverage claims;
- mechanical unchanged evidence can nominate but cannot establish semantic
  carry-forward;
- current coverage must be a cutoff-bound projection over immutable judgment
  lineage rather than a mutable validity field;
- observed tool or context activity and asserted reviewer meaning require
  separate records;
- Codebase Memory is a strong projection and navigation candidate but must not
  become the canonical review ledger;
- rich storage can reduce inference only when reviewers receive narrow
  projections and compact unambiguous output contracts; and
- a provenance gap cannot authorize review merely to make the graph complete.
