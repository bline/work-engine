# Relationships: UI Experience Evidence Interface

## Depends on: claim-centered evidence lineage

Type: causal semantic dependency on equivalent consequences; conditional owner
relationship.

Experience observations, derived provider analyses, claims, refresh episodes,
and reviewer reliance need stable identity, immutable revisions, provenance,
impact nominations, authorized refresh judgments, and exact-revision reliance.
The claim-centered proposal is the current shared-owner candidate. This proposal
depends on those consequences but does not accept its permanent placement. A
different valid owner would need to preserve equivalent distinctions.

## Informs: claim-centered evidence lineage

Type: dogfood evidence; non-authoritative.

UI observations have immutable historical truth but revisioned current
applicability, while claims carry semantic propositions and attributed refresh
judgment. A real exercise can reveal which identity and lineage semantics are
genuinely shared and where a domain profile must remain distinct. Results may
nominate changes to the parent proposal but cannot revise or accept it.

## Enables: revision-bound review artifacts

Type: optional evidence supplier; non-causal for review-artifact identity.

Revision-bound UI findings can cite exact experience states, observations,
provider analyses, accessibility probes, and claim revisions while preserving
reviewer identity, outcome, conflict, remediation continuation, synthesis, and
later applicability in the review-artifact owner. Review artifacts can still
exist without this interface; the candidate would reduce reconstruction and
strengthen evidence addressability.

## Related to: adaptive review-panel coordination

Type: consumer relationship; non-owning.

An adaptive panel coordinator may select Truth, Maintainability,
Explainability, and Aesthetics perspectives for a material human-facing change.
The selected reviewers can reuse this interface's evidence. Selection,
independence, omissions, failures, synthesis, conflicts, and downstream
authority remain coordination and review-artifact concerns.

## Producer: Chrome Vision

Type: current repository capability; not a proposal-packet relationship.

Chrome Vision supplies bounded browser facts, interaction outcomes, artifacts,
provenance, limitations, and lifecycle epochs. The experience interface can
reference those packets without moving product target meaning, navigation
contracts, evidence interpretation, or review judgment into the transport.

## Producer: product adapter

Type: prospective domain contract; not a formed packet relationship.

A consuming project owns view predicates, semantic anchors, fixtures, safe
navigation, state restoration, and cleanup. The shared façade represents and
queries their evidence but cannot manufacture product semantics or mutation
authority.

## Consumer: Work Engine Studio or another control-plane client

Type: prospective projection; not a formed packet relationship.

A future client may show experience traces, screenshots, structural evidence,
provider analysis, coverage, claim history, review findings, impact nominations,
and refresh events. Visual replay and query convenience remain projections of
domain-owned history rather than new evidence or authority.
