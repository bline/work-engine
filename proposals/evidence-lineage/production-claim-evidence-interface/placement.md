# Placement: Production Claim Evidence Interface

## Candidate owner

A repository-local shared claim-evidence capability is the probable semantic
owner of the production core. Its canonical records and transport-neutral
operations sit beneath proposal-research and review domain profiles. A Codex
skill is the primary in-repository interface; a Work Engine MCP adapter is an
external read-only projection over the same owner.

The skill does not own the claims merely because agents invoke it. The shared
capability owns record identity, schema, validation, publication mechanics,
lineage integrity, and projection semantics. Domain workflows own proposition
meaning, judgment, materiality, and transition authority.

## Rejected placements

### MCP server as canonical owner

Rejected. MCP is a transport and bounded projection. External availability,
tool registration, or server lifetime cannot own claim meaning or canonical
history.

### Codex skill instructions as canonical owner

Rejected. The skill describes and invokes the capability but model-facing prose
is not durable claim state, schema authority, or publication authority.

### Proposal packet

Rejected. Proposal packets may consume exact revisions while retaining
proposal identity, lifecycle, and decision authority.

### Review artifact

Rejected as the shared owner. Review is one domain profile and retains finding,
episode, severity, synthesis, and outcome semantics.

### Query index or graph database

Rejected as canonical semantic placement. An index is rebuildable from durable
records and exposes watermarks and exclusions. Scale evidence may change its
physical mechanism without moving claim ownership.

## Domain-profile placement

Proposal-research and review profiles live with their domain owners and import
the shared record contract. They declare authorized transitions and extension
fields without forking stable claim identity or redefining shared lineage.

## Relationship to the next phase

The dependent maintenance and reliance-propagation proposal extends this owner
with additional record types and coordinated domain transitions. It may reuse
the same skill and projection machinery, but phase-two acceptance remains
separate and cannot be inferred from phase-one placement.

## Reopening conditions

Reconsider this placement if real consumers require incompatible stable
identity or authority semantics, if a rebuildable projection cannot support
truthful discovery, if canonical publication requires an always-running owner,
or if the shared capability begins absorbing domain judgments merely to keep a
common schema.
