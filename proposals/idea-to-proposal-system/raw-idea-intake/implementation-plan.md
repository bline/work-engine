# Implementation Plan: Raw Idea Intake and Claim Assessment

This is a possible delivery shape for the formed candidate, not implementation
authority or a mandatory procedure. Steps may be combined, reordered, or
revised when another route preserves the same outcomes and ownership boundaries.

## Contract and representative subjects

Define the smallest source-binding and assessment record whose mechanically
closed fields preserve identity, exact source revision, provenance, authority,
references, current disposition, and non-authorization. Bind representative
raw sources covering duplicate, promoted, apparently implemented, split,
genuinely novel, uncertain, and no-proposal outcomes before using their results
to revise the contract.

## Validation and history

Provide deterministic checks only for closed shape, identity uniqueness, source
and proposal reference resolution, revision binding, relationship endpoints,
and consistency with separately owned dispositions. Preserve non-destructive
assessment history and demonstrate that Git retention and source movement do
not silently alter subject identity.

## Adaptive intake capability

Expose model affordances for claim identification, targeted reconciliation,
decomposition, evidence gathering, focused user interaction, partial
disposition, and reopening. Persist consequences before handoff or context loss
would require material reconstruction. Do not turn these affordances into a
fixed questionnaire or universal state sequence.

## Formation handoff

Exercise a fresh proposal former using only one bounded intake projection and
named on-demand evidence. Confirm that formation can create zero, one, or
several proposal candidates without rereading the entire raw-idea collection or
treating intake judgment as proposal authority.

## Workflow dogfood and placement decision

Run materially different intake subjects through the controlled proposal
workflow, including one decided proposal and one unresolved or no-proposal
outcome. Use observed retrieval cost, semantic corrections, source movement,
claim reuse, reviewer consumption, and cleanup pressure to decide the physical
surface, claim-lineage integration, and any richer runtime state needed.
