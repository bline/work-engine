# Private Contract B init-only acquisition

This is an **unselected offline integration**, separate from the public Host and Server entries. The Linux feature `private-init-only-acquisition` composes the existing task-free Campaign owner and the accepted Ready and scoped Terminal checkers. No default dependency enables it. It has no workload input, Builder, release, or successor path. Enabling the feature supplies no selector, installed reader, or run authorization.

## Custody and ordering

The trusted Work Engine controller holds the Campaign use port, the exact selected binding, and one capture directory outside the Builder's mounts, credentials, and control handles. The intent binds the protected root (canonical path/device/inode), Docker Unix endpoint and listener credentials, identity of the separately reviewed read-only source, and the Stop wire/time budget. The versioned Host preimage preserves both exact Unix byte paths and all four device/inode values (separate fixed eight-byte big-endian fields, not Campaign JSON numbers). Selection and the pre-spend comparison use this same pin; a mismatch refuses before endpoint preflight or archive reservation. The recipe and serving generation are independently pinned by Campaign. The deployment must protect the controller, Campaign DB, reader, socket resolution, and custody root **including their ancestors** from untrusted rename, substitution, or writes. A file owner/mode check is not proof of that installed topology. This design trusts the selected infrastructure and protected owner, not the Builder; it is not a signature against root or the capture writer itself.

The controller atomically reserves one private directory per attempt. Exclusive owner-only numbered records are chained by content digest and synced with the directory. The ledger distinguishes:

- Campaign spend, reconciled against its committed owner state;
- intent and the exact Campaign mark, then a synced `Armed` record before any request byte can be submitted;
- completion of a local request write, separately from the bounded raw response, decoded response or read/write failure;
- the exact Create reply ID (when available), created-only Inspect, prearmed stdout wire, and actual selected Start/task and live kernel coordinates;
- the original Held capture coordinate and exact applied witness, the later matched source coverage and its receipt coordinate, the matched Stop resolution scope before Arm, and independent Terminal witnesses and check results.

An `Armed` record is a conservative *may have submitted* marker. It is not evidence that Docker accepted an operation. `Written` is a completed local write observation, not a receipt or a fence. For cold recovery the protected owner can retain the serializable `RecoverySelection` (also in record 001): it addresses the original Campaign root, profile, opening, grant, attempt, selection and intent, but cannot reconstitute a binding or continuation. Campaign checks the original registration and exact spend first. Host recomputes the same intent pin from the present checked archive root and the retained lossless endpoint and source descriptions before interpreting any prefix. A mismatch or unavailable identity leaves the archive unavailable even if spend is known; there is no legacy pin fallback. This path does not resolve or connect to Docker, look up containers by name, enter Campaign, or send/replay an operation.

A torn/missing archive or an alternate custody root cannot cancel a known spend. Preserve the validated prefix, including a full Create reply ID even if its separate identity append never happened. A valid prefix cannot prove that its suffix is present or that absence of an `Armed` record rules out submission. Recovery intentionally does not read the owner's current mark/contest frontier: every spent result reports current disposition unknown, even if the archive contains a prior successful scope check. Neither history nor an exact known ID authorizes reconciliation by mutation. After crash/loss the designated disposition owner needs the exact IDs and open questions. The scoped runner does not send Remove/Delete.

## Independent checks

1. The owner-gated transport sends versioned Create, full-ID Inspect, stdout-only non-TTY live attach and Start. The source binds the exact object resolution and broadcaster registration on the actual Start and stdout channels. Socket path and listener checks do not identify the daemon generation. A socket cookie correlates a local channel; neither it nor a 101 proves the resolved object or the producer.
2. The collector timestamps completed local Start submission and polls both the reply and stdout without waiting for 204 to read stdout. The Start fence must establish that the pipe's only producer is the exact Start-associated task after that Start was accepted. Neither local ordering nor the trusted init's separately checked marker can establish that causality. After checking the original Linux pidfd/cgroup and draining stdout, the controller fixes one actual Held cut. Before Ready, the protected reader must establish continued original live task/exec/subtree, launch/root and stream continuity, and supply evidence covering that cut for the *entire* independently applied witness bound to the marked Start and actual stdout exchange/pipe. The controller checks source, exact capture and archived payload, and coverage in the capture clock, then syncs the proof before constructing the cut from that same payload. A digest proves correspondence, not that the policy applied at that time; a copied timestamp, equal observations across a gap, or a later current-state read is insufficient. Procfs and the enforcing AppArmor label also do not prove applied policy contents or complete exposure. Failure leaves spend intact but supplies no Held, Close mark, or Stop.
3. Only confirmed Held allows the qualification's one scoped `Stop(signal=SIGTERM,t=2)`. Before Arm or any write, require an already-effective restriction for the exact marked subject, original task, serving generation, method/target, and actual request channel. Sync that matched scope before submitting on that same channel. The actual handler can resolve only the original subject or the request is inert, until the handler has fixed the original target without later retargeting or can no longer select or act. Full-ID syntax, socket correlation, local send completion, partial writes, timeout, client/controller loss and task exit do not secure this horizon. The restriction must survive those events (or the request must become inert); a process-local guard cannot authorize submission. Unless proved, do not Arm or send. An existing Close mark remains possible-issue-only. The scope is not proof of issue, response, causation or Terminal.
4. Terminal uses the original pidfd's exit and `cgroup.events` from the retained original directory, after scoped ingress, old-task disposition, acceptance and recovery observations. The separate containment check must corroborate continuous containment and closed ingress/recovery through the exact final read, checked after it completes. Inability to sample the original directory after exit is unknown, not empty. A failed/lost Stop reply is diagnostic; positive independent settlement can qualify when Stop submission is established. Stop success, a missing task in a listing, and generic Delete events cannot fill an evidence slot. The independent Terminal checker is unchanged.

## What remains before a run

**NO-GO.** This commit supplies a wire/custody/verifier path, not a selected installation. The only complete source is the offline test double; the real runner fixes the Linux kernel adapter but ships no selected implementation of the residual protected source. Stock Docker Inspect/attach do not provide applied policy and exact runtime acceptance/recovery evidence. The missing integration point is the *scoped* authenticated source for:

- serving-generation identity, stable original resolution on the Start exchange, and exclusive original Start-to-task-to-prearmed-pipe causality through the final Held cut; authorized evidence of immutable startup and the entire independently applied policy, mounts, namespacing and exposure **at that cut**;
- an enforced original-only-or-inert restriction across actual Stop handler lookup on the selected serving path, with explicit coverage after client/controller loss and through authoritative original resolution or definitive inability to act;
- exact old-task disposition or equivalent effective revocation, closed same-attempt acceptance including internally delayed work, and execution-inert recovery backing with continuous containment through the final read.

Bind those facts to an already-authorized trusted-runtime/kernel source or an equivalent scoped fence. Offline tests use independently authored HTTP header and response examples, not on-host handler observations; the exact installed wire compatibility remains to be bound without spending a grant. Do not substitute requested settings, require broad runtime access, or deploy a new observer by default. Establish that the selected controller can read the required kernel paths and keep the original evidence through cleanup. The exact immutable installed init, reader/serving/artifact pins, protected custody placement, deadlines, and who owns unresolved disposition must be bound before asking for separate approval. None of that requires a successful Held or Terminal witness *before* the one authorized experiment. The actual 201/inspect/prearm and Start/marker/applied cut, task exit, original subtree contents, and exact settlement are observations of that experiment, not assumed preconditions. The default refusal, frozen Docker/containerd/runc stack and task-free scope remain unchanged.
