# Offline Rust lifecycle service (S4)

`lifecycle-service <config.json>` opens one SQLite lifecycle root, holds the S1 writer lock, then binds a local Unix socket. The socket's existing parent directory must be owned by the configured principal UID and mode `0700`; the socket is created at mode `0600`. Linux peer credentials are checked against the pinned principal before a request is read. The store actor serializes commands, grants, results, transitions and coherent target-aware snapshots. Lost socket replies do not cancel admitted commands. SIGTERM closes the entry gate, drains owned tasks for up to five seconds and stores their exact joined/unresolved/pending set with latched unsafe-close history. A new process receives a new runtime incarnation and never re-sends an entered attempt. The S3 `ReadClient<UnixSocketTransport>` can reconnect to the stable store ID and stream ID.

The command envelope is one bounded JSON line: `{"op":"command","command":{...}}`. Published v1 `request_replacement` and `request_interruption` remain supported; v1 `enqueue_input` returns `unsupported_capability` before store mutation because that payload cannot bind text or producer. V2 `enqueue_input` requires `input_id`, `producer_ref`, exact UTF-8 `text`, and `text_digest` inside the v2 command digest basis. The service checks the UID/principal, configured producer, subject/build/proof/context, pinned grant/scope and current durable grant before applying it. The result is a v2 envelope with `accepted`, `outcome_kind`, optional outcome reference or rejection code, and resulting revision. Effectful commands are not retried by the read client; replay the exact command ID and digest to recover a lost result.

The read envelope is `{"op":"snapshot","subject_id":"...","delivery_id":null,"transition_id":null}`; either target ID may name historical committed state. `{"op":"wait","subject_id":"...","cursor":{...},"target":{...},"max_wait_ms":"..."}` returns only `changed`, `no_change` or `cursor_gap` hints. Every hint causes the read client to reread store-backed state. Snapshots are v1 DTOs with current admission and target-aware history, no raw input or final response text. Frame capacity is 131072 bytes, controlled input and response text are at most 65536 bytes, concurrent entries are capped by configuration, and waits by `max_wait_ms` (at most 30000).

`profile: "read_only"` is available in the default production build, rejects commands and does not dispatch prepared work on restart. `profile: "controlled"` requires the opt-in `controlled-proof` feature and a distinct external peer socket, verifier executable and ledger path. The peer returns source/effect/attempt/incarnation-qualified text results. S2 owns execution and result capacity; S1 commits the local terminal fact and exact result before acknowledgment. A replacement is bound to one committed result source. Its exact response is a controlled continuation receipt; a separately registered S2-supervised verifier child checks the peer ledger and response hash before the checkpoint fact is committed. The store retains the verifier's primary error, activation, close disposition, exact exit and unsafe/late-close evidence separately. Other supplied continuation facts drive only reducer-allowed stages. Failed or missing external facts leave a blocked or recovery-required history. Controlled test barriers can be configured through `proof_barrier_dir`; they pause at named points but cannot mutate lifecycle tables. Optional `verifier_proof_ms` and `verifier_cleanup_ms` set bounded child deadlines (default 5000/6000 ms, cleanup at least proof, maximum cleanup 60000 ms) for controlled failure qualification.

Native provider discovery, operations, live inference, stronger same-user hostile-code isolation, production grant provisioning/rotation, S6 semantic quality, UI ownership, legacy disposition and deployment cutover are outside S4. The controlled profile is an offline proof surface, not a production provider route.
