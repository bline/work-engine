# Pi context observer

A standalone local evidence adapter for the pinned Pi SDK context estimate. Supply the current source, physical session ID, observation generation, model and positive context window from their respective owners, plus observation ID, source sequence, timestamp, provenance and nullable SDK `tokens`. A missing identity/window cannot be constructed. The caller must supply a trusted current binding, clock and maximum age; this crate cannot establish identity or freshness on its own. Numeric timestamp and RFC3339 time must agree. A distinct identity requires a distinct observer and an explicitly selected initial disposition; this does not establish lifecycle recovery. The caller remains responsible for any continuity decision. An unavailable estimate advances source ordering but does not become zero or change pressure. Replays return prior evidence; conflicting or reordered observations are rejected.

The ratio is floor(tokens/window × 10000), clamped to 10000, and is fed to the existing pressure controller under caller-selected policy. It is an SDK estimate, not provider token accounting. Transitions and low readings confer no reset, recovery, delivery or other authority. Callers own any lifecycle-level order and persistence; the source sequence here is local to one binding.

`cargo run --offline --locked < fixtures/mixed.json` runs a local example. It passes non-Pi records through unchanged; the example's budget/time values and cursor are constructed, representative `usage_ledger.py control` records, not actual expenditures or a delivery claim. `next_budget_cursor` is opaque. The adapter makes no provider requests.
