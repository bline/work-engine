## Deliverables and acceptance

1. **Repeatable operator entry.** A repository-owned Rust capability, or a
   bounded extension of an existing one, prepares/validates the local job
   bundle from explicit task, workspace, validator, limits and trusted
   authorization inputs. An operator can reproduce preparation and submit/read
   through the existing MCP/command/server surfaces using the documented entry,
   without copying the old private launcher or editing opaque generated JSON.
   Preparation performs no provider execution. Pins and paths are data; they
   do not mint authority. The existing Host admission and job credential
   boundaries remain effective.
2. **Independent fresh jobs.** Exercise two separately prepared deterministic
   jobs with fresh private state and distinct identities. Exact repeat of one
   request retains its operation; preparation or transport retries cannot
   substitute for a separately authorized new effect. Existing profile/digest
   compatibility remains covered.
3. **Deadline and quiet control.** Exercise a hanging command with a child that
   ignores graceful termination, and a healthy silent command inside its bound.
   Establish the selected owner's enforced deadline, retained partial output,
   actual exit/status collection and absence of its owned descendants. Silence
   alone must not classify healthy work as failed. Publish the tested layer:
   collector-process proof does not establish container cleanup or a workspace
   command's own deadline. Those stronger claims require actual observations
   at their owners; leave any unestablished requirement explicit.
4. **Interruption, restart and replay.** Interrupt an owned execution at a
   controlled point and restart the consumer. The caller can read the same
   operation and its established or explicitly uncertain effect state. An
   independently observed effect marker/counter detects duplicate execution;
   the adapter's own summary is not the sole oracle. Reconciliation cannot
   launch a replacement. Original receipt values survive capture/readback and
   restart; delivery acknowledgement does not establish semantic acceptance.
5. **Reviewed, collected result.** Relevant crate/process tests, formatting and
   affected lint checks pass on the exact candidate. A separately established
   read-only Astra high/default reviewer evaluates source and failure evidence,
   retaining the episode through bounded fixes. Preserve the realized capability
   grant, exact reviewed revision, findings and final disposition. Root accepts
   the exact subject, records limitations and collects every owned actor/process.

Use deterministic faults through actual caller and owner code where practical.
Name every fixture/substitute and what it can establish; an offline Host fixture
does not qualify the real Pi SDK/provider route. A required property lacking a
permitted test route stays unmet. Partial prerequisite publication may be useful,
but it is not acceptance of the full round. Narrow defect repairs within the
selected owners fit this budget; broader authority/profile changes do not.
