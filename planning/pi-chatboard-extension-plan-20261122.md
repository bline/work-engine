# Pi chatboard extension — implementation and agent timeline plan

Status: baseline design accepted by Astra xhigh after retained remediation; all four baseline slices explored and sized. The operator's subsequent `new_context` continuity requirement is included below; that delta has not been re-reviewed or separately sized. Implementation, install and publication are not authorized by this plan. Work Engine reference `f68e1eb3`; Pi package workspace reference `d0309947c8aa868f6017bb14418179c3da30399b`; tested host Pi 1.5.2 on Linux. See [timeline and evidence](#timeline-and-evidence).

## Objective and acceptance

The operator configures a coordination group once. Six normal Pi sessions (one orchestrator and five named lanes) start with no prompt, no model tool call and no manual subscription step. Matching traffic reaches a live Pi inbox; reports go only to the orchestrator, questions/commands/forwarded updates go only to explicitly named targets, and a `session:<id>` address targets the live transcript which registered it. No default `all` subscription, no startup/quiet-timeout/restart inference. After killing a listener, ordinary messages posted during the interruption arrive when the same session's listener recovers, without prompting the model. Closing Pi stops observation; resuming the same enrolled session recovers board messages from saved state. Scope excludes a daemon, cross-machine delivery, launching a closed agent, mandatory model wakes, installed skill changes, npm publication and changes to Work Engine board storage/retention.

## Placement and source contracts

- Work Engine's [`wait --follow`](../docs/codex-chatboard.md#wait-for-messages) owns exact topic and directed (`to`) matching, `--exclude-session-id`/`--wake`, row identities, inotify and board revisions. Run it via argv, not a shell and not from the model. `all` is an exact legacy topic, not a wildcard. The extension always selects explicit topics, not an empty list. Existing publishers/readers, including opt-in users of `all`, remain unchanged; native skill notices on `all` are not part of this profile unless explicitly enrolled by the operator.
- New TypeScript workspace `pi-chatboard` in the existing `pi-extensions` monorepo is the Pi-specific consumer. It owns config, lifecycle hooks, delivery, and simple publish affordances. Pi needs JS/TS to host extension APIs; no new general-purpose service or board writer. The existing `pi-agent` real-CLI fixture and workspace docs are packaging/test precedents. Keep pilot package private/local until separately approved. Repository path/package registration/lockfile are implementation work, not actions taken by this plan.
- Site config is operator-owned (agent home or explicit opt-in launch profile), read-only to the extension; repository config, message fields and model invocations of the extension cannot select executables, readers or a board. Use a trusted operator-selected Work Engine checkout/package (script, imports and kind registry), absolute outer executable paths and existing reader digest options. Supply a child environment constructed from an allowlist with an operator-controlled `PATH` for the board's nested `git` and `python3`; do not inherit Git repo/config overrides, Python import/bootstrap variables, or provider credentials. Resolve and verify the canonical Git common directory under that very environment; use it for board identity. For Pi identity, use the live session manager, not inherited IDs or a supplied message. For a new no-prompt Pi session, a runtime ID and canonical parent plus intended transcript filename suffice for local board enrollment; verify the header when a file is present. File-backed context is separately unavailable until the intended file exists and binds to that runtime ID. Never force transcript creation or a first prompt. This protects extension call targets, not arbitrary same-UID Pi tools. See [notification boundary](../docs/codex-chatboard.md#notification-boundary) for Linux, local filesystem and Git files-backend constraints; invalid identity/config or a mismatched bound source fails visibly rather than falling back.

## Profile, routing and presentation

- One group identifier per collaboration run/namespace, exactly one configured coordinator alias, unique lane aliases. An explicit operator bootstrap selection at a process startup enrolls an unbound session in a free membership; successful enrollment durably associates board, membership and Pi transcript identity. An existing associated session automatically re-enrolls on startup/resume/reload; a conflicting requested membership fails closed. In-process `/new` and fork identities are not automatically associated, even if the predecessor just released the live lease. A switch to an already-enrolled session uses that session's own stored membership; a replacement for a retired session needs an explicit operator reassignment, not reuse based on a now-idle lane. The durable association is distinct from the live lease. Board aliases are advisory routing, not role authority, ACLs or proof of sender identity/membership.
- Listen on `session:<actual-uuid>` and the corresponding stable `role:<group>-<alias>`; validate the codec with `post --to` and prevent collisions (defined component grammar or unambiguous encoding). `report` from a lane is shorthand for `tell <coordinator>`, and `tell` supports one or more explicit members; use a group-scoped message topic not used as an inbox selector, plus explicit `--to`. Direct IDs are resolved through the shared local association registry for the current board/group, not accepted as arbitrary caller text; unknown, retired, wrong-group and implicit group-wide routes fail before posting. A valid addressed row on topic `all` still matches by `to`; an unaddressed `all` row does not. The same rule applies to unrelated `job:` traffic, even if it has `wake: true`. No additional topic veto. Generated messages carry actual sender session and configured role/author as advisory provenance. Self echo is suppressed only for an opted-in filter, honoring the canonical `--wake` bypass without starting a model turn. Axes of authorization and wake policy are not inferred from the payload. Input sizes and argv are bounded; generated text is never executed.
- Preserve all `wait` batch arrays independently (including when `status=messages` with both observations), `matches`, and terminal conditions. Job completions/typed posts are messages; claims/releases are not emitted as a separate stream. Context and budget are optional **explicit** bindings; if configured, observation is automatic, validated and private to the intended local session. On reader gaps expose unavailable/error, not zero usage/spare context. A model switch, transcript epoch or budget-reader change must preserve binding provenance; a change that invalidates a cursor needs a deliberate fresh baseline, not silent reuse. A finite `--follow` timeout is total, not heartbeat, and exit 2 is a normal rearm with the final cursors. Treat `budget_closed` as a deliberate end for that binding, not a reason to stop quiet board delivery or spin restarting a closed objective. Context/budget observations are not a replayable journal during an observation gap.
- The inbox is local and bounded. Show availability, unread count, lag/gap/errors and an inspect surface. The default projection is UI/status and pull; no asynchronous Pi `sendMessage` from the reader (the default send mode can steer a busy session). If compact attributed custom observations are enabled, only drain already-committed batches in the natural user-turn `before_agent_start` hook, without initiating a run, steering or follow-up. Never use `sendUserMessage`, a prompt per event, or a raw transcript writer. Full batch is inspectable until explicitly released, never promoted to instructions. The optional natural-turn projection and local inbox acknowledge do not certify model receipt, action or authority. No active wake in the pilot, including publisher `wake: true`; `/chatboard status` is diagnostic, not required to stay enrolled. This quiet route is not a replacement for time-sensitive context/budget delivery until an operator or separately qualified wake route can act in time.

## Slice ledger

S1 and S2 can run together **after the accepted plan fixes the seam**: S1 owns the package manifest and host/subscriber files, S2 owns routing and publish files and their isolated tests. Agree filenames and types before dispatch; use isolated branches for concurrent writes, then integrate. S3 extends S1's subscriber/runtime, after S1; it need not wait for S2 if integrated on separate paths. S4 composes S1–S3 and is on their downstream critical path. A reviewer slot, worktree and integration are actual scheduling resources; do not assume unlimited parallel inference or a release gate not in scope.

### S1 — automatic Pi enrollment and live observation

Deliver: package shell and canonical profile/identity ports, fakeable `WaitInvocation` and batch/restart decoder; start and retire a per-enrollment owned `wait --follow` stream in the Pi lifecycle; live inbox intake, health and optional context/budget envelope projection. Define injectable board source, membership lookup, position/admission and Pi sink interfaces. For `from now`, obtain one authoritative **unfiltered** board-tail snapshot (`read --limit 1`, empty → 0); set that exclusive cut before starting the first waiter. Pausing between snapshot and waiter must not lose a later post. Only board sequence is cut; keep initial auxiliary observations. A deliberate `since` is permitted for backfill. S1 exercises the ports with in-memory test/admission state; S3 persists the initial cut before declaring durable enrollment ready. Include bounded frames/errors and quiet behavior; only kill the owned subprocess on shutdown/switch.

Gate: real offline Pi CLI (`--mode rpc`, no prompt), scratch Git board and pinned readers: automatic own-address delivery into an inspectable inbox, no unrelated or reserved synthetic rows, unchanged mixed batch for the configured fixture, no `agent_start`. Cover old matched history longer than a page plus a post between cut and wait. Separately start a truly new Pi session whose transcript is still absent: board traffic works, file telemetry reads unavailable, and the extension neither prompts nor writes the transcript. Check invalid config, mismatched identity/environment and clean shutdown. Cover all status/array combinations and a deterministic busy/settling Pi case in S1 or S4: `wake: true` produces no steer, follow-up or extra request.

**Budget (optimistic / likely / adverse, elapsed minutes):** builder and deterministic gates **18–28 / 35–55 / 70–110**; Astra review, repair and recheck **9–16 / 20–35 / 45–75**; slice total **27–44 / 55–90 / 115–185**. Likely build: package/profile/identity 7–10m, lifecycle and decoder 13–20m, fixtures/gates 15–25m. Allow **28–45** build requests, **12–22** Astra and **6–12** repair requests; indicative 10–70k carried input and 0.2–3k output per request, cache split unknown. Sol medium (high for lifecycle diagnosis), Astra xhigh. Biggest uncertainty: adapting the `pi-agent/test/fixtures/run-pi.ts` RPC/faux shape from its pinned 1.4.0 to installed 1.5.2. Start with no-prompt one-session own-address receive and clean EOF before expanding fixtures. The observed ~1.2s RPC probe and ~10s Python suite anchor machine time, not model latency. Medium scope / low timing confidence.

### S2 — directed publishing and group isolation

Deliver: separate `routes`/`publish` modules consuming profile, sender identity and membership lookup through the agreed ports; explicit recipient resolution and argv-only board `post`. Commands/tools: `report`, `tell` and named forwarding with an original reference and new attributed envelope. No automatic republish. Retain each intentional send's ID and canonical caller-controlled fields as a send intent. With uncertain post outcome, read back and page far enough from the pre-send cursor to classify that ID: matching caller-controlled fields confirm, mismatching fields conflict, unreadable/absent evidence is still unknown. Ignore owner-generated timestamps in reconciliation; rerunning CLI `post` can refuse on a new timestamp. An explicit retry refers to the original intent/ID, never silently generates a fresh ID. Until S4, use fixture identities/registry and a separate private intent record, not S3's inbound state files.

Gate: scratch board exercises coordinator-only report, another group with same alias, verified session routes and unregistered/wrong-group rejection, selected forwarding, invalid target/no write and untrusted payload as inert text. Inject post commit followed by lost acknowledgement: the publisher discovers the exact matching row and confirms only one intended send; conflict and still-unknown are distinct. Verify unaddressed `all` and unrelated `job:` (even marked `wake`) do not match, but an addressed `all` row matches exactly once by `to`. Preserve canonical self exclusion and these results at consumption.

**Budget (optimistic / likely / adverse, elapsed minutes):** builder and gates **25 / 45 / 80**; review, repair and recheck **15 / 35 / 65**; slice total **40 / 80 / 145**. Likely build: routes/lookup 8m, Pi commands and argv 8m, intent/reconciliation 14m, scratch routing/fault fixtures 11m, validation 4m. Allow **20–50** Sol requests including repair (0.4–2.2M aggregate input, 8–28k output) and **10–25** Astra requests (0.2–1.1M input, 4–16k output); cache split unknown. Sol medium, Astra xhigh. Main uncertainty: matching canonical caller fields across a genuinely lost acknowledgement, especially when confirmation is beyond page one. Probe that against scratch CLI before wiring Pi commands. The existing app-server adapter is a pagination precedent, not a correct substitute for full intent reconciliation. Medium scope / low timing confidence; assumes the agreed seam and isolated files, not S1 implementation completion.

### S3 — owned recovery, bounded inbox and durable per-session position

Deliver: implement the shared local association registry and per-subscription state ports. Initial cut, inbox admission, board cursor and opaque context/budget cursors are committed durably; make batch admission and cursor advancement atomic, including quiet checkpoint-only batches that take no inbox slots. Match future checkpoints to board/identity/selector and control/budget policy fingerprints; do not cross-bind. Dedup board rows by board + message ID within replayable retained scope. Fence both `(board, membership)` and `(board, session address)` **independent of selector fingerprint**; process death releases/reclaims ownership automatically and a stale generation cannot admit an event or leave an old observer live on takeover. A crash-safe lock/transaction mechanism is selected after checking installed Pi/Node (SQLite is a candidate). Scope process cleanup to owned descendants. Between budget closure and board continuation, drain the final budget batch before retiring that binding; no spin or message gap on the remaining stream. Rearm quiet exit 2, back off visibly on failure; no model rearm.

**Same-session epoch rollover:** Pi [`new_context`](../skills/manual-orchestration/references/native-context.md#pi) replaces the reasoning context, not the Pi session. Subscription ownership is tied to the enrolled session/transcript, not the model epoch or its memory. The extension handles Pi's successful `session_compact` hook and recognizes a committed `pi-context-epochs/epoch` boundary in `event.compactionEntry.details`. Reconcile the existing listener idempotently against the same enrollment after that signal; do not infer a completed rollover from the `new_context` tool call. Listener exit/error handling and session-start reconciliation still recover ordinary failures, even if no epoch signal arrives. Keep the original selectors, live context/budget bindings, committed cursors, and pending inbox across the rollover. If the listener survives, keep it; if interrupted, automatically reconnect the same subscription from the last committed position. Neither branch takes a new from-now cut, opens a duplicate listener, or asks the model to reconstruct config or rearm. Context telemetry must reflect the new epoch when available; a new epoch does not itself invalidate an otherwise unchanged binding. A deliberately closed budget binding stays closed. This does not grant enrollment to a new `/new` or fork session, or promise replay of auxiliary observations emitted only during an observation gap.

Provide an explicit local drain/ack that frees retained payload capacity without asserting the model read or acted. On overload stop advancing with visible lag and automatically catch up from the last commit when capacity returns. Bound by count and bytes; an indivisible oversize frame/event is blocked with a diagnostic, not silently dropped. Recovery is an operator increase to capacity or an explicit skip/reset showing the affected sequence interval (if not knowable, say it is not knowable, do not claim continuity) and impact on auxiliary bindings. Keep raw payloads out of global logs; projection is not the durable receipt boundary. Do not promise exactly-once model execution or replay of transient control samples.

Gate: fail before/after commit; post during outages and page through history; differentiate exit 1/2, broken stdout and closed budget. Test simultaneous same-membership/different-session and same-session/different-membership attempts, reload, switch to another already enrolled session, real persisted offline quit/resume, fresh `/new` and fork without enrollment, and abrupt host death with stale listener output. Assert no stale commits, duplicate durable admission, skipped board rows, extra inference or orphaned watchers. Test fill → pause → local drain → unattended ordered replay, one valid oversize row, and visible explicit changed-scope recovery. Use pinned fixture readings for telemetry; no claims of complete gap history.

**Budget (optimistic / likely / adverse, elapsed minutes):** builder and gates **50 / 90 / 160**; first review **15 / 25 / 45**; repair and rechecks **5 / 25 / 60**; slice total **70 / 140 / 265**. Likely build: durable transactions and initial cut 20m, dual fence and child custody 35m, bounded replay and failure fixtures 30m, deterministic gate execution 5m. Allow **35–75** Sol requests at 30–75k input and 0.5–2k output per request, **12–30** Astra requests including rechecks at 25–65k input and 0.4–1.5k output; cache split unknown. Sol high, Astra xhigh. Scout verified an in-memory `node:sqlite` transaction under Pi's bundled Node 22.23.1, not crash custody. The first risk-reduction probe is abrupt Pi death with a live nested reader and racing replacement: show no old process group survives handoff and no stale output commits. A local lease keeper with OS locks held through cleanup is only a candidate. If that ownership guarantee cannot be realized on the installed profile, qualify stronger containment or hold S3; the adverse budget is not permission to relax the gate. Medium DB/lifecycle confidence, low crash-tail confidence.

### S4 — exercise the six-session operator path and package the pilot

Deliver: private local package and operator example with coordinator + five lanes; deterministic real-host test scenario exercising the joined artifacts; usage/limitations, rollback (disable profile/unload, no repo state conversion), diagnostics and open limits. Bind tested Pi version, source checkouts, config and install path. No live operator profile changes, provider calls, or release. Any rollout/runtime change needs explicit downstream adoption of tooling instructions; the pilot is not automatic enrollment for unrelated sessions.

Gate: six Pi CLI sessions on one scratch board using setup before any prompt. Routing matrix with wrong-recipient negatives, leader fan-in and selected fan-out; unaddressed `all` ignored, directed `all` delivered once, unmatched `job:` with wake ignored. Model-free queueing; listener kill and unattended recovery of posts made during outage; genuine persisted resume/switch without duplicate watcher; board unchanged aside from intended posts. `/chatboard status` is diagnostic only. Include a busy/settling offline scripted-model case (no network) showing `wake: true` adds no steer, follow-up or request. Smoke-test quiet visibility in a real TUI/PTY or explicitly keep that path unqualified. Measure local delivery and recovery latency as observations, not provider timing claims. Run focused Python board/context/budget suites, extension unit/offline host tests and **targeted private-package checks**: registered local workspace, declared Pi entry loads, and excluded from publication (the public-workspace manifest loop skips it). Docs must use exact accepted config/behavior.

**Epoch qualification:** In one of the enrolled Pi sessions, exercise a real `new_context` transition with a credential-free fixture and verify the epoch changed while the session ID and transcript path stayed the same. Post matching and nonmatching traffic across the boundary, with an unread pre-boundary event. Verify the original filters and bindings, retained unread event, no duplicate admissions or second watcher, and no subscription/rearm action in the new epoch. Also test an interrupted listener across the boundary: qualifying board traffic posted while disconnected replays from the last commit without resetting the cut. Distinguish Pi's native continuation turn from any model wake caused by the extension. A simulated reload alone does not qualify this case.

**Budget (optimistic / likely / adverse, elapsed minutes):** builder and gates **25 / 50 / 95**; review, repair and recheck **12 / 25 / 50**; slice total **37 / 75 / 145**. Allow **14 / 26 / 45** Sol build requests, **5 / 10 / 18** Astra review/recheck and **2 / 6 / 14** Sol repair; indicative 20–45k input and 0.5–2k output per request, cache split unknown. Sol xhigh, Astra xhigh. Six ready processes can start concurrently within measured host capacity; the fault scenario has a real enrollment → listener death → outage post → replay dependency. Package and existing regression checks may overlap if inputs and scratch state are isolated. First cheap probe: pinned, credential-free RPC with a faux model held on a fixture barrier; post a wake-marked event mid-run, verify inbox delivery, unchanged queue and no extra request. The previous wake fixture never reached the socket. Medium sizing confidence; the six-session gate, real local package load and optional PTY visibility are not yet qualified.

Retain one board cursor plus its selector/identity scope and a bounded durable inbox. No context-pressure or budget readers, auxiliary cursors, mixed observation dispatch, budget-closure logic, or new telemetry extension in this estimate. `new_context` is only a Pi lifecycle signal for messaging; it does not require a context-pressure extension. Keep the board source intact and the model-free/quiet delivery, lost-ack reconciliation, dual ownership fencing, genuine epoch, and six-session gates.
