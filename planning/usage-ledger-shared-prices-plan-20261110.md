# Usage ledger: one shared API price table

Prepared 2026-11-10 by Claude Code session ff2f77ed (claude-opus-5-5) at the
owner's request ("plan this now and begin implementation"). Outside any
campaign; no scope_budget limits set.

## Why

API prices live in three places today:

| Copy | Read by | Kept equal by |
| --- | --- | --- |
| `metrics/scripts/usage_ledger.py` `CODEX_RATES`, `NATIVE_RATES`, `API_TIER_MULTIPLIER`, `PRICING_RULES` | `build`, `tree`, `control`; every budget monitor | (source) |
| `skills/manual-orchestration/scripts/openai_api_rates.json` | Pi egress proxy `--max-usd` (`pi_container.py:79`) | `tests/test_pi_container.py` |
| `skills/manual-orchestration/scripts/anthropic_api_rates.json` | Pi Anthropic route (`pi_container.py:106`) | a parity test |

No Rust crate carries prices yet (searched `rust/crates/*.rs`, 2026-11-10). A
future Rust engine that prices its own provider turns will need the same data
and the same arithmetic. Python literals cannot be shared, and a fourth copy
would be one more thing to keep equal.

## Owner

The usage ledger owns API prices and the pricing arithmetic: the two skills
files name it as their source. That does not change. The price table moves
out of the ledger's source into a data file that the ledger owns.

## Invariants

1. **Same inputs, same outputs.** For any input, `build`, `tree` and
   `control` produce the same output as before the change. Only the reader
   provenance fields (`reader.sha256`, and the new price-table digest) differ.
2. **The ledger digest still decides its prices.** Monitors and session-events
   pin `usage_ledger.py` by sha256. The ledger embeds the sha256 of the price
   file it accepts and refuses any other bytes, so a pinned ledger digest still
   fixes the prices it applies.
3. **A missing or invalid price table fails closed.** The ledger does not
   fall back to built-in prices or price at zero.
4. **API prices are separate from uncertainty and quota policy.** Unknown-tier
   bounds (`unknown_tier_low/high`) and Codex subscription quota ratios
   (`QUOTA_MULTIPLIER`) are ledger policy, not provider prices, and stay in the
   ledger.

## Required consequences

- One price file that a non-Python reader can load: JSON with a named schema
  (`work-engine-api-prices-v1`), each provider's source URL and the date the
  prices were read, citing `metrics/probes/price-table-addendum-20261110.json`.
- Golden vectors: (provider, model, usage, tier) → expected API-equivalent USD,
  generated by the **current** ledger before the change. Then:
  - the refactored ledger must reproduce them;
  - a later Rust implementation verifies against them, which is the
    cross-language check `docs/rust-development.md` asks for.
- Every consumer that copies the ledger also gets the price file:
  - **manual-host bundle:** `provision_manual_host.sh` copies only `*.py` from
    `metrics/scripts`. It runs in place from the repository, so the fix takes
    effect at once.
  - **session-events `support/`:** a staged copy of the ledger alone. It gets
    the price file at its next release, and until then keeps running its pinned
    old ledger.

## Phases

**Phase 1 (this session).** Price file and verified loader in the ledger.
- The ledger keeps exposing `CODEX_RATES`, `NATIVE_RATES`,
  `API_TIER_MULTIPLIER` and the price entries of `PRICING_RULES`, now built
  from the file. The skills parity tests and `pi_container.py` therefore need
  no change.
- Add golden vectors, and copy the price file into the manual-host bundle.
- Work on branch `ledger-shared-prices` in its own worktree. Integrate into the
  main checkout only after the checks below pass and no running monitor pins
  the current digest.

**Phase 2 (after the Pi P2 release decision).** `pi_container.py` reads the
shared file, or a release-time copy verified by digest, and the two skills
copies are removed. This changes the qualified Pi runner, so it needs its own
requalification and a skill release with owner approval. Not started.

**Phase 3 (when a Rust component first has to price a call).** A Rust package
loads the same file and passes the golden vectors. Its placement and owner
follow `docs/rust-development.md`. Not started, and no consumer exists yet.

## Checks (phase 1)

1. Golden vectors: generated from the pre-change ledger, reproduced exactly
   after the change.
2. Test suites: `metrics/scripts/tests` (usage ledger) and the manual-orchestration
   tests that pin rates.
3. Output equivalence:
   - Run the old and new readers back to back on the same snapshot:
     - `build` over a closed past window;
     - `tree` on closed objective records.
   - Diff the outputs after removing `snapshot_at`, `observed_until` and the
     reader provenance fields. Expected difference: none.
4. Fail-closed:
   - a missing, altered or schema-invalid price file stops the reader with a
     named error;
   - a test proves the embedded digest rejects altered bytes.
