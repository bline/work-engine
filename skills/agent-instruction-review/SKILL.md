# Agent Instruction Review

Review an immutable, revision-bound subject and return advisory findings. Do not
edit the subject, choose architecture, form or accept a proposal, select a
panel, approve implementation, or treat persistence of a finding as evidence.

The review applies to materially normative text consumed by agents, wherever it
is stored. File type and imperative wording are candidate signals, not proof of
applicability or structural necessity. For proposals, apply the review only
when present proposal content creates or changes an instruction, loading or
precedence contract, or an exact route claimed as mandatory. Truthfully omit a
proposal that merely anticipates a future instruction artifact.

## Diagnose the instruction

For each material instruction, ask:

1. What distinction must remain true for the governed outcome to stay valid,
   safe, authorized, or observable?
2. Does correctness require this exact route, sequence, trigger, or mechanism?

These questions are reasoning affordances, not a sentence-by-sentence form or
a closed taxonomy. Preserve an exact route when reversing or replacing it would
lose the named distinction. Otherwise distinguish invariant structure from a
current mechanism, default, example, observation, or recommendation. Split
bundled text when its clauses have different effects.

Judge placement relative to the text's semantic owner, intended consumer,
authority source, scope, precedence, audience, and loading behavior. A local
mechanism can be correctly placed without becoming general doctrine. Similar
wording at project, role, skill-entrypoint, conditional-reference, adapter, and
example layers can warrant different conclusions.

Treat `DESIGN.md` as binding only for the product structure it explicitly owns.
Treat `PHILOSOPHY.md` as non-normative reasoning. If both matter, preserve their
different effects. Name any other authority source rather than silently
promoting preference or current repository knowledge into a command.

Investigate only the neighboring context needed to establish owner, consumer,
loading reach, causal necessity, and consequence. When the underlying
capability owner or governing authority is unresolved, report that limitation
to the owning architecture or decision role instead of deciding it here.

## Return evidence-bearing advice

Read [references/finding-contract.md](references/finding-contract.md) before
recording findings or an applicability omission. Keep results compact and bind
them to the exact subject revision.

Ordinary remediation may return to the same retained reviewer so it can
evaluate its own findings against an exact new subject or bounded delta. That
continuation does not create a new freshness or independence claim. Reset is a
judgment for changed premise, material placement or architecture change,
unusable context, contamination, or a renewed independence need.

The author or builder decides whether an advisory finding is valid and performs
authorized mutation. The named decision owner retains acceptance authority.
This skill cannot certify its own implementation; bootstrap evidence must use
an independently defined review contract and fresh reasoning context.
