# Historical S5 item inspection

Role Scheduler owns the SQLite item identity, recipient, due time, current status and acknowledgement reference. The bounded `historical_s5.inspect.v2` adapter reads one exact item under a current local inspection grant. Its Rust reader enters a kernel-enforced no-filesystem-write domain before opening the database, uses a read-only SQLite connection, takes one snapshot for store revision and row, verifies the selected-row digest, and emits an allowlisted summary. If that domain cannot be installed or SQLite needs to create or modify WAL companions, the read is unavailable. `query_only` or the SQLite read-only flag alone is insufficient because SQLite can initialize side files. The adapter does not call the scheduling daemon, initialize the store, take a due item, finish an item, or write a result.

The retained S5 row is currently `acknowledged` with `presented_at` null and a result ref to an exact review revision. The store has no mutation journal for this item. A consumer may display the current acknowledged row and exact result ref, but cannot reconstruct presentation, execution order, or a provider-result UUID causal edge from it. That limit is visible in the terminal view because an apparently complete timeline would overstate what this owner retained. This is a read adapter for a fixed historical case, not a second scheduler state owner.
