## 2. New-defect checks requested

**(a) Per-call resend rule cannot be abused to skip continuity.** The rule is evaluated between consecutive wire payloads with `previous` always advanced (`:410`). Cases: interleaved ids `[r1 A, r2 B, r1 A]` → B→A requires A to strictly extend B, `next.len() <= prev.len()` → refused (`lib.rs:88`); reversed order `[r2 B, r1 A]` → refused likewise; an id reappearing with different bytes `[r1 A, r1 A′]` → `resend-differs`; `[r1 A, r2 B, r2 B]` → ok (byte-equal). Across the runner, all payloads of one id are necessarily byte-identical because each `request-<n>` is read from the single file `coding-hosted-<n>.body.json` and re-digested (`pi_host.rs:452-466`), so a later reappearance always carries the shorter/equal body and is refused. The selected payload is `(inference_call_id, physical_send)` from the causal call (`research_delivery.rs:701-706, 722-724`), so a resent call does not trip `multiple-selected-wire-payloads` (q4's call names `request-1`/send 2, the completed attempt). Only the runner-unreachable shape `[r1 A, r2 B, r1 C⊋B]` would pass the task-host check alone — see P3 #5.

**(b) Host early reading preserves order; no relay answer or request is lost.** `controller_ended()` drains with `try_recv` into `queued` by `push_back` (`pi_host_serve.rs:353-358`); `next_message` always pops `queued` before touching the inbox (`:334-348`); every consumer (`relay` `:712`, `wait_controller` `:370`) goes through `next_message`. Hence FIFO is preserved. A relay answer cannot be queued before its request is sent (the relay loop is synchronous and no `controller_ended` call interleaves), and queued requests are answered by `wait_controller` after the turn, exactly as inbox requests were. `None` is always the reader's last send (`:93-118`), so "ended" detection via `any(is_none)` is complete; after `None` the sender drops and `try_recv` returns `Disconnected`, which the loop treats as end-of-drain. The unit test asserts the early-read `thread/read` plus `None` stay queued in order (`:1482-1483`).

**(c) Refusing frames after controller end strands no container, misreports no finished turn.** The `coding_history` frame is exempt (`:1028`), so a turn Pi genuinely finished is still reported `completed` with its capture; any other frame is refused, the Host run fails, and `Host::run` records the failure and proceeds to `coding_hosted_abort` → `reconcile()` → collect: stop/kill a running container, `rm`, `confirm-removed` (`pi_docker.rs:1097-1109, 1158-1230`). `finish()` then fails the still-active turn with the Host's first recorded failure, and the queued `None` ends `wait_controller` (`pi_host_serve.rs:283-331`). In the relay-waiting case `Ok(None)` sets `closing` and refuses (`:720-722`), so `finish` does not block.

**(d) Runner capture checks agree with `build_capture`.** Host writes `inference_call_id: "request-{n}"`, `physical_send: k` (attempts start at 1: `provider_attempt` requires `attempt == previous+1`, `:1062-1069`), `path: state_dir/coding-hosted-{n}.body.json`, `representation: "wire"`, `original_codec: "identity"`, `sha256` of the file (`:898-930`); `not_dispatched` attempts produce no payload; `total` is summed per attempt in both (`:924` vs `pi_host.rs:465`). `calls[*].{inference_call_id, physical_send}` name a completed attempt whose payload was pushed (`:936-966`). `observation` is added by `finish_turn` when a history frame exists (`:797-808`) — and is only required for *eligibility*, not acceptance, so a turn failed before history is still retained. Tools digest: Host `digest(serde_json::to_vec(&body["tools"]))` before dispatch (`pi_coding_analysis.rs:146`, called from `pi_coding_hosted.rs:828`) equals the runner's computation (`pi_host.rs:481-483`); same workspace, no `preserve_order` anywhere (grep of `Cargo.toml`). q4 artifacts: capture eligible with the resend shape `(request-1,1 refused) (request-1,2 completed) (request-2,1)`, `summary.json` `eligible:true`, `payloads:3`, `recovery:"CompletedSettled"`, protocol `604f1a10…`; `CompletedSettled` is reachable only through `check_capture` passing, so the new checks accepted a genuine capture in that build.

**(e) Mid-turn close wait is bounded.** Drain ≤ `turn_deadline+60` s, reap ≤ 10 s (`pi_host.rs:626-638`). The Host notices end-of-input within its own turn deadline (attempt dispatch deadline `a.deadline_ms`, `active()` refuses past `a.deadline`, `relay` bounded by `until.min(a.deadline)`), which started earlier than the runner's budget, so the Host normally exits well inside it. The actor's shutdown path waits for the runner task past its 7 s budget by design, recording `cleanup_unobserved` (`actor.rs:2506-2542`, pre-existing). See P3 #2 for a tighter bound.
