## What is correct (evidence)

**1. Conformance to the lifecycle consumer (once L/S/T land).**
- `turn/completed` carries `params.turn.{id,status,error}` with `error` present and `null` on success, `{"message"}` on failure (`pi_host_serve.rs:620-623, 636-639`); matches `native_input.rs:154-160` and `lifecycle-codex/protocol.rs:224-262` (`terminal()` needs `threadId`, `turn.id`, `turn.status`).
- `item/tool/call` params: `threadId, turnId, callId, namespace, tool, arguments`, `id` numeric (`:661-666`); decoder `tool_call()` needs exactly these, `namespace` ≤64 chars (`protocol.rs:184-222`); actor classifies by `namespace` `workspace`/`task` (`actor.rs:1825-1852`); `namespace()` maps the three pinned tools (`native-realization/src/lib.rs`, `tools::namespace`).
- Controller answer shape required: `{"success": bool, "contentItems": [{"type":"inputText","text"}]}` with exactly those two keys (`:691-703`); the actor produces exactly that (`actor.rs:2199, 2418`).
- `item/completed` `dynamicToolCall` item: `id, namespace, tool, arguments, status: completed, success, contentItems` (`:705-706`); the store compares arguments and the single `inputText` (`native.rs` operation check), and `thread/read` items must equal the completed items (`tool_completions.get(call) != Some(item)`): the Host stores and serves the same `Value` (`:716-718`, `view()` `:321-327`).
- `agentMessage`: `item/started` with `"text": ""` then `item/completed` with text; history messages compared ignoring `id` — the Host reuses identical items (`:600-611`). Final answer = last `agentMessage` (`operations/mod.rs:827-833`), bounded to 64 KiB (`:552-556`, store `65_536`).
- `thread/read` reply is a Response (`method` absent) with `thread.{id, historyMode: "legacy", turns[{id,status,itemsView:"full",items}]}` (`:371-373`); matches `native.rs` history checks and the runner (`operations/mod.rs:811-826`). `history_status` resolves to `observed_complete` because tool items are present.
- Capture: payload keys `inference_call_id request-<n>`, `physical_send` = attempt, `representation: wire`, `original_codec: identity`, `sha256`, `path` (`:898-901`); calls bundle `call_id, inference_call_id, physical_send, response_id, namespace, tool, arguments` (`:925-927`) — the keys `research_delivery.rs:452-486, 503-507` and `native_causal.rs:103-110` read. r4 capture shows the join `toolu_1_0 → request-1 / send 2 / msg_1` after a 429 on attempt 1.

**2. Fail-closed behaviour and custody.**
- Provider requests fenced: `provider()` requires `correlated` (session, invocation, turn) and `id == provider_calls+1`, no pending command (`:460-471, 497-506`); `provider_attempt` requires `request == provider_calls`, strict attempt order, granted route/payer, an active un-expired turn, ≤64 sends, and passes `min(turn deadline, job deadline)` to dispatch (`:1001-1037`); the hosted path uses it as the attempt deadline before any upstream byte (`pi_coding_hosted.rs:1183-1190`). Frames after the job deadline are refused (`:975-978`).
- Relayed reply sent once and equal: `dispatch` rebuilds the expected `snapshot_result` from the controller's answer and refuses a second send (`:1042-1055`, test `:1311-1316`). Pi's native completion must carry exactly the relayed text and `hostReportedSuccess` (`pi_coding_analysis.rs:425-437`).
- SDK-refused tool calls never reach the controller (`sdk_refused_ids`, `pi_coding_analysis.rs:346, 411`); any `toolCall` block without a relay fails the items (`:745`), and a relay absent from Pi's messages fails too (`:764-766`).
- Controller error, malformed answer, EOF or timeout during a relay → refused → Host job fails → `finish()` reports the active turn `failed` with the Host's first failure and an ineligible capture (`:683-690, 297-306`; n1 run: `"the Host job ended during the turn: controller refused tool call toolu_1_0"`, `thread/read` shows `status: failed`, no containers left).
- Turn after a failed turn refused (`thread_failed`, `:413-414, 629`); `turn/start` while a relay waits → `-32000 a turn is active` (`:673-677`).
- Eligibility: settled (`:869`), no pending/uncertain (`:884`), last attempt completed (`:887`), body digest matches retained body (`:893`), bounds (`:912-917`), each call joined to exactly one model tool call with a response id in a completed attempt (`:908, 925-931`), history present (`:934`), observation succeeded (`:572-582`), frame bound (`:605-609`). Capture written create-only before `turn/completed` (`:613-619, 636-639`).
- No credential/account leakage: capture holds paths, digests, route ids and payer labels only; `contains_account_identifier` flags `metadata.user_id.account_uuid` (`:876-883`); stdout carries protocol frames only (binary writes the record to stderr, `bin/work-engine-pi-host.rs:38-45`); the only other `println!` in the crate are `main.rs` and a test (`pi_native.rs:976`).

**3. Protocol vs implementation** — honoured: initialize-once/first, `thread/start` model + exact `dynamicTools` (`:235-247`), one non-empty text input (`:395-401`), notification order (r4 `protocol.jsonl`), `pi-host/capture` by turn (`:375-387`), observe refused during a relay wait and after the container is gone. Deviations: #2, #5 above; also the spec's "Not answered during a turn" is realized as *deferred* (queued until the turn ends) except during a relay wait — acceptable but worth one sentence.

**4. Shared-path regressions** — none found. `is_analysis` now includes relay (`pi_coding.rs:56-58`), which routes relay through the analysis gating (`analysis_profile()`: no tool-container collection at request 2, `OUTPUT_BYTES`, `check_answer_bound`, native-end check); the analysis profile's own branches are unchanged because every relay difference is behind `is_relay` (`validate` `:404-411`, `ready_tools` `:98-100`, `profile_tools`, `coding_snapshot_frame` `:243-245`). `check_request_tools`/`check_messages_tools` take `schema` and all three callers pass it (`pi_coding_hosted.rs:838-841, 893-897`, test `pi_coding_analysis.rs:572`); non-relay digests unchanged. Deadline cap: only fresh relay jobs get 3 600 s, everything else 300 s (`pi_docker.rs:257-267`). The Responses relay digest is zero at the commit and refuses every Responses relay request (committed `RELAY_TOOLS_SHA256`), as the record states.

**5. H5 observation** — it does re-verify containment: fresh `docker inspect --type container <name>` under the digest-pinned Docker client (`pi_coding.rs:792-801`), then the launch verifier `verify()` (Id equals the journal's container id, Name, image, labels, user, Cmd, no network, read-only root, `CapDrop ALL`, memory/pids/cpu, `no-new-privileges`, exact mounts, env prefixes; `pi_coding.rs:669-777`), plus `State.Running` and no `/auth*` mount (`:810-823`). The container name is Host-generated `we-pi-<24 hex>` (`pi_docker.rs:437`) and passed as a single argv element (no shell), so no injection; output bounded at 1 MiB after the read (#8).
