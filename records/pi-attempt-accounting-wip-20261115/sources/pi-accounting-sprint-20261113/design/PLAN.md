## Stage and representation correction

Use the existing stages with one explicit **post-V financial finalization** boundary F:

`E → C → {S, V} → F → X → K`, with pricing primitives shared leaf inputs to S and V. S may inspect raw usage for the producer-consistency check; it never consumes V's valuation result. C owns correlation and raw identity/lane facts; K does not determine lane, completeness, money or placement.

S outputs `SettlementDecision`, execution/forwarding facts and `TemporalObligation = Outstanding | Closed{by} | None{cause}`. `Closed` requires a valid settlement and exact key join. F reads C/S/V facts, including pre-K identity-set establishment, and produces `Replacement` plus `amount_source: SettlementAmount | ReservationConfirmed | ReservationBound | None`. Every reservation-backed result has an amount source, including Outstanding. None is reserved for no reservation. The external obligation object is a generated projection combining temporal state and F's amount source; S no longer claims to construct replacement-dependent metadata. X computes exposure; billing status is then derived from its high, under the stated usage evidentiary standard. No provider bill is manufactured.

Example: VC01 and U08 can both be temporally Closed by Valid(Usage). F gives VC01 eligible/SettlementAmount, U08 ineligible/ReservationBound; U08 retains `AtLeast(max(R, charge, usage high))`. A06 can be Outstanding with ReservationBound without inventing a field on a fieldless enum.

## Gate trust interface and non-circular assumption

Raw `GateAssertion` is untrusted data. A future adapter produces `GateVerification = Unverified | Rejected{reasons} | Verified{authority_id, verifier_identity/version, trust_policy_ref, payload_digest, verification_evidence}` bound to the exact gate/session/period/currency/coverage/numerical ceiling and admission authority. Only the adapter-controlled boundary may construct trusted verification input; raw JSON cannot acquire it by setting `writer=authority`, `verified=true` or matching a digest. Qualification still checks scope, period, mechanisms, cap coherence and contradictory execution facts.

The trust assumption is external and explicit: the owning vertical establishes the authority identity, trusted verification channel/anchor, realized enforcement and evidence custody independently of the gate assertion and accounting generator. Neither a hash nor a private type establishes those world facts. S1 specifies this input contract and missing/failed verification behavior; it does not implement keys, signatures, authentication or production enforcement.

Synthetic positives use an unmistakable `test_mock` verification source supplied through a separate fixture-harness input bound to the exact payload digest. The output/evidence records that assumption. Mock data inside producer log bytes cannot mint verification. Fixtures establish only behavior conditional on trusted input; no S1 fixture qualifies a live producer or authority. Forged P1.34 receipts remain negative even if every raw field/hash is internally consistent. Existing cooperative legacy closure is not silently upgraded to authenticated authority.

## Independent oracle and invalidation

The oracle worker receives pinned raw lines/rates, owner dispositions, producer writer excerpts and historical findings. It computes expected outcomes from those sources without importing canonical generator/evaluator logic or accepting generated derivations as proof. Shared schemas/encoding may validate shape, while semantic derivations remain independent. Each case records raw-input digests, field/policy interpretation, arithmetic, expected tagged result, finding IDs, producer-reachability standing and a writer-consistent witness or explicit uncertainty. Preserve historical case IDs/raw evidence/results; corrections are separately justified new expectations with old-to-new records.

Oracle results are sealed before comparison. A generic result comparator may compare independently supplied expected/results; neither generator nor builder writes oracle expectations to make a comparison pass. Disagreement returns to root and the oracle owner. Independently reviewed positive controls prevent a reject-everything tool from passing.

S1 has no raw financial evaluator: structural checks reject structural counterexamples, while the independent oracle owner and required semantic reviewers check the canonical guarded rows/formulas against sealed raw-derived assertions and calculations. Record those as attributed semantic review, not executable reducer conformance. If the approved S1 tooling cannot mechanically decide a financial assertion, report that limitation; do not add a reference reducer or treat a generator pass as evidence of the assertion. Executable whole-reducer conformance belongs to S2a.

Registered edges connect node revisions/content digests to rendered blocks, schemas, invariants, case assertions, producer witnesses and review acknowledgements. Any body or dependency digest change invalidates acknowledgements throughout the reverse registered closure, even if an author forgets to bump a semantic revision. Generated views rebuild; independent expectations remain frozen and are marked needing reassessment. Re-acknowledgement needs a substantive disposition, not just a new hash. Missing IDs/cycles in stage dependencies/unresolved approvals fail checks. This catches **registered** dependencies only; root/review still assesses omitted conceptual dependencies and all affected boundary consumers.
