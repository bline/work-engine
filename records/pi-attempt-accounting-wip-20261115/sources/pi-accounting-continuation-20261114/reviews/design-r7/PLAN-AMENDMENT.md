## 2. C-owned primary membership and exact F application

Add a minimal computed `primary_memberships` relation to AccountingResult. Each record contains `obligation_id`, `reservation_classes` and `settlement_classes`. Each class contains a nonempty, unique, canonically sorted `origin_refs` set and a `representative_origin_ref` that belongs to it. It enumerates all original primary origins, including admitted exact copies, for that obligation and role. Classes are disjoint by origin. Representative choice is deterministic equality bookkeeping; it is not a test of physical identity or a parser for IDs. Admitted evidence equivalence alone permits multiple origins in a class. Same-origin reobservation is idempotent; equal amounts or decoded JSON do not establish equivalence. C-primary owns this computed relation. No chosen membership or validity is put in AccountingInputProof.

The supplied-record consumer checks that each PrimaryValidity has exactly one matching membership record and that its `distinct_reservation_refs` and `distinct_settlement_refs` are exactly the corresponding representative sets. It rejects missing/dangling/duplicate/multiple membership, an origin in both primary roles, or evidence-class application unsupported by the admitted exact-copy relation. The finite independent raw claims establish exhaustive membership, classification and equivalence against the actual raw primary inventory; supplied-set coherence alone does not claim that derivation.

For an accepted budgeted coverage: its obligation_id equals its selected PrimaryValidity's obligation_id. Its selected whole hold units supply precisely its monetary/anchor origins. Every reservation and settlement origin in that obligation's membership classes must occur in the covered monetary inventory, and the covered primary inventory may contain no primary evidence from a different obligation. Validity remains a C-owned witness with all checks; the unique count is evidence-class count, separate from reservation max arithmetic. A changed witness, changed membership or added primary evidence invalidates dependent coverage.

Represent exact admitted link identity explicitly. Add `link_id` to InputLink and DefiniteLink. A result DefiniteLink's `admitted_input_link_ref` names the exact InputLink `link_id`, never its grant ID. InputLink still names the admitting grant; its exact endpoint pair must be contained in that grant's admitted payload/extent. DefiniteLink must preserve that exact pair. Coverage `definite_link_refs` names exact result link IDs. A grant authorizing several pairs does not make those pairs interchangeable.

Every released anchor must have a cited link whose exact endpoints are that anchor and a usage-bearing request/primary origin covered by this coverage. Reject self-links, uncited links, another request's links, wrong endpoints and links supported only by grant existence. The same rule applies to the unbudgeted-completion route, with the exact completion's request origins replacing primary obligation membership. Display attachment, n equality and source completeness alone still establish no DefiniteLink.

The selected ValuationRecord's `usage_origin_refs` must equal the covered usage-bearing origins for that same obligation/completion, including applicable covered auxiliary usage, and may not borrow another request's usage. Necessary identity contexts remain read-only references through the declared financial-candidate relation and do not become a second covered monetary occurrence. The independent finite claim fixes the exact usage-bearing origin set; structural checking enforces its equal application across selected valuation and coverage. If existing fields cannot distinguish that set, add only a C-owned computed usage membership set to the same membership/completion record, with the same raw-qualification obligation. There is no opaque-ID inference.

Preserve total origin ownership, whole-unit coverage, overlap/conflict rules, retained charge/context components and the separate UnbudgetedCompletion boundary. Strengthening applicability must not silently turn an invalid dollar settlement into an unbudgeted request, remove an unresolved zero anchor or reduce retained high.
