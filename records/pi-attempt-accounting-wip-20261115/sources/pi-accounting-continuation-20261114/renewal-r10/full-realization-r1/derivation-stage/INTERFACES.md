# Typed finite-qualification interface proposal

Standing: proposal for root binding only; no source/schema/consumer implementation is admitted by this document. Keep AccountingInputProof, AccountingResult and independently authored ExpectedDossier distinct. Existing result records remain supplied claims. Both actual consumers receive a root-selected trusted dossier independently of the mutable subject path. A subject, registry or command-line value inside that subject cannot choose or weaken expectations.

`DossierHeader` binds version, author identity, source manifest, policy/rate refs, full required universe digest, case/evaluation/objective tuples and exact required ClaimIds. RequiredUniverse contains all175 case identities,179 ordered evaluations,187 objective configurations and374 named closed/outstanding scopes; it is independently admitted before output reading.186 is historical attempt baseline only. Root binds future unit selectors from independently derived memberships rather than imposing186 as an upper bound.

`SourceRef` identifies file digest, exact JSON token byte span/digest or source/position/raw UTF-8 digest, with tagged Presence(Absent|Null|Value(type,lexical_value)). Arrays preserve order, duplicates are rejected and object inventory is explicit. Raw numbers retain decimal lexemes for exact representation. These coordinates locate evidence; they are not executable JSON-path expressions. Runtime predicates use closed typed fields and typed selectors. Opaque CaseId/EvaluationId/ObjectiveId/OriginId/UnitId/ScopeId/LinkId equality supplies no semantics.

`CausalAdmission` fixes complete inputs, ordered evaluations excluding expected, presence-sensitive trusted_fixture_inputs, profile/schema/contract/case/role and every additional causal channel. It includes complete top inventory, explicit reasons for exclusions, and separate qualification sideconditions for historical/profile consistency and revision records. PayloadPremise names a typed guarantee kind, namespace, exact origins/extent, external document and uniquely resolved fragment. Source hashes, matching grant IDs and this extraction's located proof documents do not establish admission. A missing grant or unresolved fragment has RequiredUnmet status and cannot enter a qualified dossier.

`ClaimStatus = DerivedNominal | RequiredUnmet(reason,owner) | Unexamined(next_evidence)`. This stage's raw inventories and authored partial arguments do not automatically become DerivedNominal records at case-family granularity. `QualificationOutcome = Qualified | Failed(predicate,detail) | OutsideAdmission(reason) | RequiredUnmet | Unexecuted`; these are distinct. Missing/duplicate/unrequired/inapplicable claims and unresolved selected refs cannot be converted into skips or pass counts.

`ConsumptionRecord` binds consumer kind/version/binary, source/dossier/universe/schema identities, case/evaluation/scope/claim variant+ID, applicable premise IDs, actual selected result/unit/ref targets, applicability outcome, evaluated predicate ID, consequence outcome and control/custody refs. A Qualified record is emitted only after both admission and the required current consequence succeed. Required and visited counts cannot stand for evaluated or qualified counts. Root reconciles complete required/evaluated/qualified/failed/outside/unmet/unexecuted sets, with explicit duplicate rejection.

Actual Python full `check_corpus` must perform independent full admission before each required finite consequence in check_case/check_attempt/check_accounting_references/check_evaluation and fail when full dossier is missing. Keep legacy structural checks useful and pilot separately bounded. Independent Rust `independent_raw_axes` must independently implement the same finite predicates against current selected outputs. It cannot delegate monetary truth to Python or generator decisions. Shared serialization, hashes and exact parsers are permissible; shared expected financial derivation is not.

The present token inventory is evidence navigation, not this executable interface. All172 payload references now have exact lexical fragment locations:108 use source_origin_id,64 use the explicit cases[].case_id/initial_reference_scope_payloads[].grant_id shape. These locations establish no grant authority. Root must bind each lawful fixed payload type and independent admission or preserve it unmet. No general expression language, raw attribution/financial reducer or partition solver is needed by these shapes. Root must reject or escalate any variant that cannot be realized within D3 without one.
