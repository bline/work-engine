R9 supplied-reference interface (spec owner, 2026-11-14)

AccountingResult.primary_memberships is required whenever primary_validities is nonempty (optional empty otherwise). Each entry: {obligation_id, reservation_classes, settlement_classes, usage_origin_refs}. Each class: {origin_refs: nonempty unique lexically sorted string array, representative_origin_ref: lexical minimum member}. Entries correspond exactly one-for-one with PrimaryValidity by opaque obligation_id. Origins are disjoint across classes/roles/obligations. Distinct refs equal representative sets. Multi-origin classes require a single admitted exact_copy_equivalence grant covering the class, matching raw_bytes_sha256 for every origin and scope_exact_line contracts sharing the same scope_id; amounts/decoded JSON never establish equivalence. usage_origin_refs is the C-owned complete usage-bearing inventory; accepted budgeted coverage must contain it and selected valuation must equal it. Independent oracle establishes raw completeness.

InputLink and DefiniteLink require unique link_id. DefiniteLink.admitted_input_link_ref equals exact InputLink.link_id and preserves directed from/to. Coverage.definite_link_refs equals selected result link IDs. Grants for exact_row_coreference require admitted_payload: either {from: origin_id, to: origin_id} or {pairs: [{from, to}, ...]}; no other keys/shapes. The projection preserves the finite payload endpoints, retains exact_payload_ref, and is supplied-record evidence only: oracle must bind it to the pinned referenced raw payload. Covered origin extent alone does not admit a pair. Self-pairs fail. Unknown shapes fail. No namespace-wide link guarantee is supported in this pilot.

UnbudgetedCompletion requires usage_origin_refs (nonempty, includes usage_origin_ref), preserving its genuine_unbudgeted applicability without any obligation_id. Selected valuation equals that complete set. Every released anchor requires a cited result link joining it to a covered primary or usage member for the selected budgeted obligation, or covered usage member for the selected completion. Coverage monetary/anchor sets must be disjoint. All selected membership primary origins must be monetary-covered, with no other obligation primary origin. Read-only context origins do not become covered money.

Existing public validate_accounting_bundle and real `evidence` command remain entrypoints. Old corpus with nonempty validity but absent memberships or old link/grant/completion shapes is deliberately incompatible; no 175-case migration is authorized. This is structural supplied-record checking, not raw derivation or money qualification.

R5 admitted extension (ORGANIZATION-R5.json / ORGANIZATION-DECISION-R5.json): AccountingResult.retained_components optional array of {component_id, origin_ref, role: reservation|claimed_reserved|charge|usage, nano_usd: canonical nonnegative decimal string matching ^(0|[1-9][0-9]*)$}. Unit.retained_component_refs optional unique lexically sorted component IDs. An inventoried component must be cited by its origin's active unit; every unit citation must name a component whose origin belongs to that unit. Coverage.retained_component_refs resolves exact component IDs and each target's origin must be covered, or be an explicit financial_candidates.context_origin_ref whose usage_origin_ref is covered (read-only context does not become covered money). Duplicate inventory IDs, dangling origins/refs and wrong unit/coverage owners fail. Full required P9 role/origin/amount inventory and rejection of wholly omitted inventory remain independent finite-claim obligations; structural checking does not infer absent components from raw. No component ID parsing or financial arithmetic is added.
