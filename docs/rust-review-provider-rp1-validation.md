# RP1 Claude transport and retained-session custody

RP1 adds a provider-disabled implementation mechanism to the Rust execution-evidence owner. An offline Rust peer exercises the same bounded Claude JSON envelope parser, durable capture, checked reader, and retained-session checks that an installed profile would use. The installed profile is inert in RP1: there is no production entry-permit constructor, permanent-host composition, production model selection, or live provider execution in this slice.

The qualified path reserves evidence custody and records `prepared`, `session_ready`, and `launch_intent` before the launch syscall. A pinned guard inside the RP0 Bubblewrap boundary verifies the candidate read-only mount, writable session mount, and CBM socket and executable mounts before the host sends the prompt. The guard receives access material and the prompt over framed stdin after its ready signal; the CLI process gets an allowlisted environment. The direct offline peer is a distinct test profile and root. The guarded offline peer uses a real candidate-private CBM index and relay, with the CBM process and its observed request count held outside the peer's writable surface.

A successful response must have one exact observed model, the requested session, a successful transport route, a bounded and duplicate-free JSON envelope, and a canonical implementation-review v1 result for the selected subject. `capture_complete` contains the bounded raw response and stderr, canonical result, observed identity, CBM observation when guarded, and immutable per-attempt session snapshot manifest. Terminal publication verifies that complete capture. Reopening can finish that original capture or replay its terminal reference; all earlier or torn states remain unresolved and cannot launch. The reader recomputes the pinned command digest and complete production-path observation from the capture, verifies the exact event and artifact inventory, and refuses a controlled root as a qualified root. A locator is descriptive; only a checked reader can issue the private retained-session capability.

Session files are copied through Linux `openat2` beneath a verified live directory with no symlink traversal. A conservative 64 MiB aggregate charge counts live files, every retained snapshot, in-progress or orphan storage, and per-entry directory/name metadata; a new snapshot is reserved against that whole charge before creation. The guarded peer sees a private 16 MiB tmpfs instead of a writable host session bind. Before Bubblewrap executes, its process enters a private cgroup v2 with a hard `memory.max` equal to the page-rounded space left by all retained host session custody and `memory.swap.max=0`. The kernel charges the peer, tmpfs data, and inode/dentry metadata to this group; process memory also consumes the limit, conservatively. The pinned guard verifies its own membership, the realized memory limit, zero-swap policy, and zero current swap charge before READY. If delegated memory or swap control is unavailable, launch refuses before the prompt. The synthetic root, `/dev`, `/proc`, and the cgroup quota view are read-only while the bounded session and scratch mounts remain writable. A hostile offline regression grows empty files until the kernel quota records exhaustion, then checks unresolved custody and no relaunch. After peer exit, the guard enumerates through directory descriptors and opens files beneath the session root with no-follow resolution. It rejects changed identities and oversized sparse logical lengths before reading, then reads through the remaining 16 MiB hard cap. The host validates the bounded export frame before importing any live files. Complete capture follows file syncs, bottom-up nested-directory syncs, the snapshot directory and parent syncs, and the evidence-root sync. Any failed sync leaves the attempt unresolved before `capture_complete` or `session_evolution`. The immutable initial snapshot remains readable after live state evolves. An owner-authorized custody registration can add a later immutable per-attempt manifest linked by exact predecessor attempt and digest; a reopened reader verifies the whole chain and current live state before issuing a later retained capability. RP1 provides only a test-gated offline registration permit, so this mechanism grants no later inference entry. Unregistered changes, missing state, links, predecessor corruption, or anchor replacement refuse capability issuance. RP2/SC3-H own later inference authorization and composition.

Synthetic credentials alone test descriptor-relative access projection, expiry horizon, file replacement, and canary exclusion. RP1 pins the selected source file for its initial attempt; RP0's established access-only projection still admits safe rotation. A token is never included in a prompt, command line, result, observation, session snapshot, or failure record. A canary in output is rejected before durable capture. Credential faults before the launch syscall are recorded as definite local pre-entry refusals. After intent, timeout, EOF, malformed output, or local reap does not establish remote non-entry or cancellation; the original attempt remains unresolved and is never retried by recovery.
