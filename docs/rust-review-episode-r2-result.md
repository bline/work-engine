## Resulting behavior and candidate

The new `review-episode-store` owns the existing SQLite STRICT tables, private offline roots, schema/integrity validation, conditional current/history writes, and closed-copy import. The new `review-episode` library and `work-engine-review-episode` binary run one bounded, length-prefixed request per process through an exact-digest offline fixture admission port and the R1 reducer. Operations are begin, resumeInitial, transition, validateResult, recover, read, and history. The only R1 code change adds `JsString`-accepting UTF-16 constructors; existing `&str` constructors delegate to them. No R0 reducer semantic decision changed.

The first actual-binary vertical initialized a disposable root, admitted begin and record_result, exited after each operation, then reopened for the exact first revision, latest state, recovery and two-row history. Later tests exercised every operation and action. Episode-bearing JSON remains the R1 UTF-16 `JsValue` representation through wire, admission digest, reducer, SQLite raw canonical bytes, and reply; a lone-surrogate transition ID and value survived restart and exact replay. Fixture statuses are synthetic and identified as `offline_fixture` in responses. JSON data does not confer authorization: the executable requires an explicit offline profile and a private registry outside the request, and each grant binds exact request digest, selection revision, root, and observed revision. A compile-fail doctest verifies private admission-result construction.

The store validates complete selected histories, exact raw canonical state bytes, identity/revision/predecessor/current agreement, retained transition digests and one new handled ID per successor. It accepts global sequence gaps and episode interleaving. Full-store validation checks every identity, SQLite integrity and history high-water. Writes reread the admitted snapshot inside `BEGIN IMMEDIATE`, distinguish busy from revision conflict, perform a conditional current update, and roll back ordinary failures. Exact replay does not append; replaced writers cannot replay their old command. An ambiguous commit/rollback closes the connection and reports `OutcomeUnknown`; a new authorized read/recover determines durable state.

The copy route accepts an explicit closed, self-contained offline SQLite file and SHA-256 manifest, checks no sidecars/aliases, validates all source rows, imports in a hidden staging root in one transaction, preserves raw rows, explicit sequences, `sqlite_sequence` presence/value and `user_version`, reopens and compares rows/counters, then publishes by rename. `reconcile_closed_copy` validates a published destination after a lost response. The success report includes source/destination file hashes, schema profile, declared provenance, episode/row counts, optional high-water/version and byte-comparison result; physical SQLite file hashes need not match. Rejection returns a typed first error identifying the first failing table, identity, and history sequence when a row fails, and retains the source. It does not enumerate every rejected row in one response.

## Review and handoff limits

The focused R2 gates ran against a stable shared isolated root/lock but are not a whole-workspace integrated gate; C2 was separately finishing its source. The parent integration owner must bind the final C2/R2 candidate and S1 handoff before recording that gate. No real copy, live DB, production native host, claim lookup, provider, independent reviewer episode, three-store correction settlement, response-time budget, deployment or cutover was exercised. R3 owns real host admission and launcher/file capability, RC owns correction joining, R4 owns real-copy qualification, and R5 owns cutover/rollback. Generated-copy manifest provenance is a declaration rather than source-custody proof. Offline private Unix directories reduce accidental substitution and other-user access but do not exclude a hostile same-UID process or establish a race-proof sandbox.

Requested builder model was `gpt-6-sol`/high. Independent attestation of effective runtime model and quantitative latency measurements is unavailable. A bounded review has not yet closed, and this result does not claim final R2 acceptance.
