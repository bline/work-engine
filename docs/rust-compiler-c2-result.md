## Implemented boundary

- The pure `work-engine-compiler` adds a verified-source comparison path without filesystem or process access. Its types move schema-validated input through source-byte and complete-projection comparison. A pure comparison stays **unverified**; only the executable sets `runtime_requirements.verified_sources` and recomputes its digest after source capture and, for roles, observed Python completion.
- The one-shot Rust executable retains protocol v1 and adds strict, correlated protocol v2. It captures canonical source, every binding, pinned projection, Python script, invariants, and environments as bounded regular-file bytes. Lexical paths retain distinct capture identities, including symlink paths. It stages captured Python inputs privately and invokes the unchanged Python owner with `/usr/bin/python3 -I -B`, then checks the complete AEG envelope and pinned projection. A role-free or unverified operation does not invoke Python. Its direct Python child is killed and reaped on tested cancellation, timeout, pipe overflow, and malformed-output paths; success requires exit 0 and empty stderr.
- The Node adapter explicitly selects a SHA-256 checked Rust binary, executes a private copy in a process group, bounds and validates the entire response and exit observation, and returns a Node `Buffer`. `WORK_ENGINE_COMPILER_BACKEND=rust` opts in; unset/default `legacy` stays on the existing JavaScript compiler. Selection failure does not fall back. The real CLI publishes a complete same-directory temporary file by rename, preserves the mode of an existing regular output, refuses output symlinks, and preserves old output on compile refusal. `--compare` mismatch publishes the valid compiled output but exits nonzero with `compare_match:false`, preserving its pre-existing semantics.
- Retained review found replacement-decoding gaps in the CLI and manifest hydration, plus BOM stripping in the adapter. The CLI and all four role/secondary compiler-YAML reads now use fatal UTF-8 decoding of original file bytes; the adapter retains a valid UTF-8 BOM when checking a Buffer. Invalid UTF-8 in either CLI YAML input refuses before publication, role/secondary hydration refuses invalid bytes, and BOM-prefixed Buffer and equivalent string inputs retain the same raw input hash.
