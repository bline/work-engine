## Selection

One session (Sonnet 5.5) chose the task. It runs no arm.

- **Chosen: R2-E2.** This is the comparison contract and finding: subcommand
  `compare` and the comparison `check` kinds, crate `proposal-evaluation`, binary
  `work-engine-evaluation`. It comes from run `r2-pressure-controller-20261022`.
  - Baseline: `f2fe643d9d29170a1421fa04ba02cc44db5ba7c9`, the accepted E1 final.
  - Accepted final: `928570a6`.
  - Rejected candidate: `e479bcb2`, the first full E2 candidate, which review sent
    back.
- **Runner-up: R2-P1** (`portfolio-decision`).
- **Why this task.** Its contract fixes the CLI, flags, exit codes, schemas and
  codes before implementation, so the packet can state the interface without
  leaking the solution. It also has a recoverable rejected candidate, and its
  baseline rebuilds offline in a single-ref clone.
- **Hazard-class gap.** R2-E2 is in the same family as the anchor: pure logic and
  format validation, with bounded file reads.
  - The candidates in other classes were B1a and B1b (protocol, stream,
    persistence). Neither is replayable under §4 T0:
    - no fixed interface: the layout was the worker's choice;
    - for B1b, the recorded baseline does not match the worker's recorded file
      hash.
  - Hazard-class spread therefore remains open for the T0 bank in Stage B.
- **Historical effort:** 3 builder contexts plus 1 fix agent, about $4.66 and
  2.96 Mwt (registry `usd`, partly `candidate` attribution, unverified against
  billing). It describes the task and ranks nothing.

exactly. The clone held 0 refs, and every build succeeded.

| baseline `f2fe643d` | 2 pass, 85 fail | 2 pass, 69 fail | 10 fail, 1 indeterminate | 1 | contract 14, historical 5 |
| accepted final `928570a6` | 87 pass | 71 pass | 11 pass | 0 | 0 |
| rejected candidate `e479bcb2` | 87 pass | 71 pass | 6 fail, 5 pass | 0 | historical 3 |

- **Baseline.** The 2 contract passes are E1 regression cases, which should pass
  because E1 exists at the baseline.
- **The rejected candidate is caught only by historical cases.** The contract
  category passes it 87/87. The builder expected the contract category to catch
  it; that prediction failed.
  - Consequence for E1b and E2: on defects of the kind review found here, contract
    cases alone detect nothing. Historical cases are the sensitive measure for
    this task, and they are a sample of defects someone once found.
  - The builder judged one of those defects contract-ambiguous, so it is encoded
    as historical only.
- **Sensitivity.** The builder applied 9 hand mutants to a copy of the final's
  `compare.rs`, and all 9 were killed.
  - This was run before 3 boundary contract cases were added, and was not rerun on
    the final 98.
  - Two mutants were each killed by a single case.
  - Not mutated: serialisation, rederive logic, CLI argument handling, frontier and
    limitations.

## Limitations (from the builder, content-free)

- **Passing the final is not completeness.** The 87/87 and 11/11 were reached
  after fixture corrections. The corrections were for:
  - nullable-key and projection rules that the baseline E1 checker enforces but
    the contract does not state;
  - `--out` not creating parent directories.
- **The fixtures follow the baseline E1 checker.** Arms have the baseline code,
  so they can discover those rules.
- **Historical coverage is partial.**
  - Not encoded: review items about partial writes (not testable here), and two
    diagnosis-only items on which the contract is silent.
  - One historical case compiles against public library paths. The packet states
    those paths (contract §5), so the case tests a stated interface.
  - Two historical cases are FIFO no-hang checks. They hang if rerun in a stale
    directory; the scorer always uses a fresh one.
- **Loosely pinned shapes.** For stored-pointer failures, exit code and report
  layout are pinned only loosely. Those cases accept exit 1 or 3, and match codes
  anywhere in the output.
- **Not covered:** concurrency, other hosts, very large inputs, i64 extremes,
  unicode ids, and E1 behaviour beyond two regression cases.
- **Size.** The historical builder needed 3 contexts on about 4.3 kLoC. A Haiku
  arm may run out of context; size it with a pilot.

## Independent re-review after repair

**Who and how.** The same independent checker did the re-review, with the owner's
approval. It diffed `battery.py`, `world.py` and `README.md` against the
pre-repair copy, and judged from the diff and the case code. It ran no case.
`TRACE-SEALED.md` now carries the per-case results in a "Re-review after repair"
section (sha256 `4580e05913027cb73134143414ab560133d2bf47e26b759496a1e90b40e44a79`).

| Check | Result |
|---|---|
| Cases changed vs the 36 flagged | exactly the 36; 0 unflagged cases changed, 0 flagged cases unchanged |
| Rewritten contract cases | all 11 now trace (10 `traces`, 1 `traces_inferred`); 0 over-constraining remain |
| Retags | all 19 agree with their clauses (sentence-level `(I)` reading) |
| `historical_diagnostic` / `historical` split | exactly the 5 flagged and the 6 in the stated interface |
| README scoring notes | hold for every case |
| Absent refusal code scored `indeterminate` | `should_fail` for all 11 rewritten refusal cases |
| Shared code-matching helper (bare substring anywhere) | weakens 22 unflagged cases' code check (upper bound); 1 has a plausible false pass |

- **The 11 refusal cases.** The packet names the code for every refusal, and the
  check ignores layout. So a refusal that prints no code at all is detectable as
  a failure without over-constraining.
  - The repair's switch to `indeterminate` under-counts failures.
  - Fix: the refusal-code helper fails instead of abstaining.
- **The 1 weakened case.** Its code word is a common substring, so a bare match
  can pass falsely. It needs a bounded match.
- **The other 21 weakened cases** are low risk and need no fix.
- **Cases still needing a fix: 12.**
- **Separate reporting of the new category.** The checker did not check whether
  the scorer reports the new category separately. The coordinator's revalidation
  output shows it does: `historical_diagnostic` is its own key in `counts` and
  `failure_families`.
